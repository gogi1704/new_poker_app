# Офлайн-режим турнира (без интернета)

Запускает тот же TD-панель + API, но на локальном Postgres на ноутбуке, а не
на облачной базе. Нужно для турниров на площадке, где есть локальный Wi-Fi,
но нет интернета.

**Жёсткое ограничение:** Telegram сам требует интернет. Поэтому бот и
мини-апп игрока в этом режиме не запускаются вообще, а игроки не могут сами
зарегистрироваться или сделать чек-ин через телефон. TD добавляет каждого
участника вручную в панели (поле «Имя нового игрока» на экране чек-ина) —
это единственный способ добавить игрока офлайн, и это ожидаемо, не баг.

## Один раз, заранее, пока есть интернет

1. В терминале на ноутбуке, в папке проекта:
   ```bash
   docker compose -f docker-compose.local.yml build
   ```
2. Скопировать `.env.local-offline.example` в `.env.local-offline` и заполнить
   `JWT_SECRET` (любая случайная строка, например `openssl rand -hex 32`).
3. Поднять только базу:
   ```bash
   docker compose -f docker-compose.local.yml up -d postgres
   ```
4. Применить миграции к локальной базе (с хоста, не из контейнера) — PowerShell:
   ```powershell
   $env:DATABASE_URL_UNPOOLED = "postgresql://pokerclub:pokerclub@localhost:5432/pokerclub"
   pnpm --filter @poker/shared db:migrate
   ```
   (Эта переменная окружения, заданная прямо в терминале, имеет приоритет над
   `.env.local` — безопасно, ничего в обычном dev/prod не трогает.)
5. Создать клуб в локальной базе:
   ```bash
   pnpm --filter @poker/api local:init-club
   ```
6. Поднять всё остальное:
   ```bash
   docker compose -f docker-compose.local.yml up -d
   ```
7. Открыть `http://localhost:8080`, зайти в настройки клуба (⚙) и задать:
   - пароль для входа в браузере (раздел «Вход в браузере»);
   - название и логотип клуба.

После этого шага образы собраны и база настроена — дальше интернет не
нужен, можно просто `docker compose -f docker-compose.local.yml up -d` на
той же площадке/ноутбуке в будущем.

## На самом турнире (без интернета)

1. На ноутбуке: `docker compose -f docker-compose.local.yml up -d`.
2. Узнать LAN-адрес ноутбука: `ipconfig`, искать `IPv4-адрес` в секции
   активного Wi-Fi-адаптера (например `192.168.1.42`).
3. С любого другого устройства в той же сети (телефон TD, табло на телевизоре)
   открыть `http://<этот адрес>:8080` и войти по паролю.
4. Дальше всё как обычно: создать турнир, на экране чек-ина добавлять игроков
   полем «Имя нового игрока» (вместо QR/Telegram), раскладка мест, старт,
   горячие клавиши (пробел — пауза/старт, ← → — уровень), отметка нокаутов,
   публикация результатов.

## После турнира — перенос результатов в облако

Делается на машине с интернетом и доступом к обычной (облачной) базе — не
обязательно на том же ноутбуке, если файл экспорта скопирован на неё.

1. Экспорт из локальной базы (имя турнира или его id — id в панели не
   показывается, поэтому проще по названию):
   ```bash
   pnpm --filter @poker/api local:export-tournament -- "Название турнира" ./export.json
   ```
2. Импорт в облако (использует `.env.local` как обычные скрипты разработки):
   ```bash
   pnpm --filter @poker/api local:import-tournament -- ./export.json
   ```
   Повторный запуск с тем же файлом безопасен — импорт пропускает турнир,
   если он уже перенесён (проверка по названию + дате).

## Известное ограничение

У игрока, добавленного вручную офлайн, нет связи с его настоящим Telegram-
аккаунтом. Если он потом откроет бота — получится второй, отдельный профиль.
Для разовых офлайн-турниров это нормально; автоматического объединения
профилей пока нет.
