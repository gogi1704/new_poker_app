# Офлайн-режим турнира (без интернета)

Запускает тот же TD-панель + API, но на локальном Postgres на ноутбуке, а не
на облачной базе. Нужно для турниров на площадке, где есть локальный Wi-Fi,
но нет интернета.

**Проще всего — через `packages/offline-launcher`**: обычное Windows-
приложение с окном. Один статус наверху и одна кнопка под ним — «Запустить»:
в первый раз она сама сделает всё разовое (сборка образов, миграции, клуб),
во все следующие разы — просто быстро поднимет стек. Остальные ручные кнопки
(«Настроить / пересобрать заново» и т.п.) спрятаны в «Диагностика и
расширенные действия» — туда заглядывать в обычной работе не нужно. Делает
все шаги этого файла автоматически, включая генерацию `.env.local-offline`. Собрать
установщик: `pnpm --filter @poker/offline-launcher dist` (нужен уже
установленный Docker Desktop и один раз выполненный `pnpm install` в корне
проекта) — готовый `.exe` (запускается без установки) появится в
`packages/offline-launcher/release`. Ниже
описано то же самое руками, на случай если приложением пользоваться неудобно
или нужно разобраться, что именно оно делает.

**Единый адрес.** Приложение само поднимает один адрес —
`http://localhost:9000` (и такой же на LAN-IP для других устройств) — который
сам решает, онлайн сейчас или офлайн, и соответственно отправляет запросы либо
в облако, либо на локальный сервер. Открывать и использовать нужно именно
его (кнопка «Открыть панель» и список LAN-адресов уже на него и ведут), а не
`:8080` напрямую — хотя `:8080` тоже продолжает работать как раньше, просто
без автопереключения. Чтобы это работало бесшовно (сессия/вход не рвётся при
переключении), нужны оба шага ниже — пункт 2 (клуб с тем же id, что в
облаке) и пункт про `JWT_SECRET`.

**Жёсткое ограничение:** Telegram сам требует интернет. Поэтому бот и
мини-апп игрока в этом режиме не запускаются вообще, а игроки не могут сами
зарегистрироваться или сделать чек-ин через телефон. TD добавляет каждого
участника вручную в панели, на экране чек-ина: начинает печатать имя —
если человек уже открывал бота раньше (и успел попасть в список, см.
«Перед турниром» ниже), он найдётся по нику и добавится под своим реальным
аккаунтом; если нет — кнопка «+ Новый» заведёт ему офлайн-профиль с нуля.

## Один раз, заранее, пока есть интернет

**Если планируете использовать единый адрес (автопереключение онлайн/офлайн,
см. выше) через offline-launcher** — порядок важен: сначала в блоке
«Облачная синхронизация турнира» подключите облако и выберите турнир, и
только **потом** в первый раз нажмите «Запустить». При такой
последовательности приложение само создаёт локальный клуб с тем же id, что у
облачного — это нужно, чтобы вход/сессия не рвались при переключении между
облаком и локалкой. Если нажать «Запустить» раньше (или настройка уже была
сделана до этой функции), локальный клуб останется со своим случайным id —
автоматически это никто не исправит задним числом (намеренно: безопасная
починка задним числом означала бы либо менять id уже существующей базы, либо
гадать, что хотел пользователь), а значит придётся либо один раз соединить
cloud sync до первого «Запустить» на чистой базе (`docker compose -f
docker-compose.local.yml down -v` сбросит локальный Postgres, если турниров
там ещё не было и терять нечего), либо просто продолжать пользоваться `:8080`
напрямую без автопереключения — тоже нормальный вариант, просто без единого
адреса.

Шаги руками (то же самое, что делает кнопка «Запустить» при первом нажатии):

1. В терминале на ноутбуке, в папке проекта:
   ```bash
   docker compose -f docker-compose.local.yml build
   ```
2. Скопировать `.env.local-offline.example` в `.env.local-offline` и заполнить
   `JWT_SECRET`. Если единый адрес не нужен — любая случайная строка (например
   `openssl rand -hex 32`). **Если единый адрес нужен** — скопировать туда
   значение `JWT_SECRET` ровно из серверного `.env.production` (одно и то же
   значение в обеих базах — это и позволяет токену, выданному одним backend'ом,
   проверяться другим). Это разовый шаг — значение не перегенерируется при
   повторных запусках, пока файл существует.
3. Поднять только базу:
   ```bash
   docker compose -f docker-compose.local.yml up -d postgres
   ```
4. Применить миграции к локальной базе (с хоста, не из контейнера) — PowerShell:
   ```powershell
   $env:DATABASE_URL_UNPOOLED = "postgresql://pokerclub:pokerclub@localhost:5432/pokerclub"
   pnpm --filter @poker/shared db:migrate
   ```
   (Эта переменная окружения, заданная прямо в терминале, имеет приоритет над
   `.env.local` — безопасно, ничего в обычном dev/prod не трогает.)
5. Создать клуб в локальной базе — без аргумента получит случайный id (ок,
   если единый адрес не нужен); с id облачного клуба как аргументом — получит
   тот же id, что в облаке (id клуба виден в облачной панели или через
   `select id from clubs` в облачной базе):
   ```bash
   pnpm --filter @poker/api local:init-club -- <id-облачного-клуба>
   ```
6. Поднять всё остальное:
   ```bash
   docker compose -f docker-compose.local.yml up -d
   ```
7. Открыть `http://localhost:8080` — вход без пароля (в офлайн-режиме он не
   нужен) — и в настройках клуба (⚙) задать название и логотип клуба.

После этого шага образы собраны и база настроена — дальше интернет не
нужен, можно просто `docker compose -f docker-compose.local.yml up -d` на
той же площадке/ноутбуке в будущем.

## Перед турниром — подгрузить настройки, участников и список игроков из облака

Если турнир уже создан и часть игроков уже зарегистрировалась через бота (пока
есть интернет), это можно перенести в локальный стек вместо того, чтобы
заводить турнир и игроков заново руками. Можно повторять сколько угодно раз
по мере новых регистраций — вплоть до выезда на площадку.

Через **offline-launcher** это происходит само: пока подключение к облаку
настроено (блок «Облачная синхронизация турнира»), раз в минуту сами
обновляются и выбранный турнир, и **весь список игроков клуба** — не только
записавшиеся на этот турнир. Именно это и позволяет на чек-ине находить по
нику любого, кто хоть раз открывал бота, даже если он не регистрировался на
этот конкретный турнир заранее.

Вручную (без лаунчера), только для самого турнира:

1. Пока ещё есть интернет: откройте **облачную** TD-панель (обычную,
   `poker-td....`), у нужного турнира (неважно, «Запланирован» или «Идёт
   регистрация») нажмите «⬇ Выгрузить» — скачается файл.
2. На **локальной** (офлайн) TD-панели — `http://localhost:8080` — нажмите
   «⬆ Загрузить из файла» рядом с «+ Новый турнир» и выберите скачанный файл.
3. Турнир появится в локальном списке с текущими настройками и всеми, кто уже
   зарегистрировался. Повторная загрузка (например, за час до старта, когда
   записалось больше людей) обновит тот же турнир, а не создаст дубликат —
   если локально по нему уже ничего не делали (чек-ин/старт/публикация).

## На самом турнире (без интернета)

1. На ноутбуке: `docker compose -f docker-compose.local.yml up -d` (через
   launcher это кнопка «Запустить» — она же поднимает единый адрес на `:9000`).
2. Узнать LAN-адрес ноутбука: `ipconfig`, искать `IPv4-адрес` в секции
   активного Wi-Fi-адаптера (например `192.168.1.42`), либо список в
   launcher'е (он уже с правильным портом).
3. С любого другого устройства в той же сети (телефон TD, табло на телевизоре)
   открыть `http://<этот адрес>:9000` (единый адрес — launcher настроен) либо
   `:8080` (без автопереключения) — вход без пароля, он не нужен в офлайн-режиме.
4. Дальше всё как обычно: создать турнир, на экране чек-ина добавлять игроков —
   начать печатать имя, и если человек уже есть в списке (см. «Перед турниром»
   выше), он найдётся по нику сам, а если нет — кнопка «+ Новый» заведёт
   офлайн-профиль с нуля, — раскладка мест, старт, горячие клавиши (пробел —
   пауза/старт, ← → — уровень), отметка нокаутов, публикация результатов.

## После турнира — перенос результатов в облако

**Основной способ — через бота, без терминала.** Доступно только владельцу
клуба (owner).

1. Опубликуйте результаты турнира как обычно. В списке турниров у
   завершённого турнира появится кнопка «⬇ Выгрузить» — она скачает файл
   турнира на устройство TD.
2. Когда снова появится интернет, откройте Telegram и отправьте этот файл
   боту **как документ** в личном чате (обычное «прикрепить файл», не нужно
   ничего набирать). Бот сам распознает файл, перенесёт турнир в облачную
   базу и ответит сводкой (сколько игроков, результатов, начислений рейтинга).
   Повторная отправка того же файла безопасна — бот предупредит, что турнир
   уже перенесён, и ничего не продублирует.

**Запасной способ — через консоль**, если отправить файл боту неудобно
(например, нет доступа к тому Telegram-аккаунту, который владелец клуба).
Делается на машине с интернетом и доступом к обычной (облачной) базе — не
обязательно на том же ноутбуке, если файл экспорта скопирован на неё.

1. Экспорт из локальной базы (имя турнира или его id — id в панели не
   показывается, поэтому проще по названию):
   ```bash
   pnpm --filter @poker/api local:export-tournament -- "Название турнира" ./export.json
   ```
2. Импорт в облако (использует `.env.local` как обычные скрипты разработки):
   ```bash
   pnpm --filter @poker/api local:import-tournament -- ./export.json
   ```
   Повторный запуск с тем же файлом безопасен — импорт пропускает турнир,
   если он уже перенесён (проверка по названию + дате).

## Если на ноутбуке пропало и снова появилось питание

Это именно про отключение электричества на том же ноутбуке (не про Wi-Fi-роутер —
потеря роутера не мешает самому ноутбуку: контейнеры общаются друг с другом
через внутреннюю сеть Docker, а не через роутер). Ноутбук не выключается сам
по себе при короткой просадке питания, но на всякий случай — вот что сделать
один раз заранее, пока есть время:

1. В Docker Desktop: **Settings → General → "Start Docker Desktop when you log in"** —
   включить. Тогда после включения ноутбука/выхода из сна Docker поднимется
   сам, без ручных действий.
2. Контейнеры уже настроены на `restart: unless-stopped`, а база — на
   отдельном Docker-томе (`docker-compose.local.yml`). Это значит: как только
   Docker Desktop снова запустился, сам стек (postgres/api/web-td)
   поднимется автоматически, данные турнира не теряются.
3. Если автозапуск Docker Desktop сработал не сразу (бывает, что он
   запускается медленнее, чем ожидаешь) — запустите
   [`scripts/start-offline.ps1`](../scripts/start-offline.ps1) (правый клик →
   «Выполнить с помощью PowerShell»). Он сам подождёт, пока Docker будет
   готов, и поднимет стек. Можно запускать сколько угодно раз — ничего не
   ломает, если всё уже работает.
4. По желанию — чтобы это происходило совсем без ручных действий: один раз,
   пока есть время и интернет, зарегистрировать тот же скрипт как задачу на
   вход в Windows (команда ниже создаёт задачу с именем `PokerOfflineStart`,
   запускающую скрипт при входе в систему под текущим пользователем):
   ```powershell
   schtasks /create /tn "PokerOfflineStart" /tr "powershell.exe -ExecutionPolicy Bypass -File \"<путь-к-проекту>\scripts\start-offline.ps1\"" /sc onlogon
   ```
   Удалить задачу позже: `schtasks /delete /tn "PokerOfflineStart" /f`.

Итог: даже при внезапном отключении света посреди турнира — после
восстановления питания стек поднимается сам (или одним запуском скрипта),
без переустановки и без потери данных турнира. Таймер при этом остаётся на
паузе, как его оставили (см. `tournament_clock_state` — он завязан на
метки времени, а не на то, что сервер «считал» всё это время) — ровно то
поведение, которое нужно: локально поставили на паузу, продолжили, когда всё
снова заработало.

## Известные ограничения

У игрока, добавленного вручную офлайн, нет связи с его настоящим Telegram-
аккаунтом. Если он потом откроет бота — получится второй, отдельный профиль.
Для разовых офлайн-турниров это нормально; автоматического объединения
профилей пока нет.

Турнир, который уже синхронизировался между облаком и локалкой до того, как
появился единый адрес (автопереключение), локально хранился под случайным
id, отдельным от облачного. После обновления первая же синхронизация этого
турнира не найдёт совпадения по id и создаст локально вторую, отдельную
копию — старая версия останется лежать рядом как дубликат. Разово, по месту
— если увидите задвоенный турнир в списке, просто удалите старую копию.
Автоматической миграции старых копий нет (разовая ситуация, не стоит того,
чтобы её автоматизировать).
